# ARCHITECTURE – langxyne

How this implementation meets SPEC.md. Standard-library Python, 3.11 or later for `tomllib`, plus the optional `jsonschema` package, run inside the build container, plus the container's `rustfmt`, which lays out the four Rust outputs, and `gofmt`, which lays out the Go output: the emitters render each construct in one plain form and the formatter decides the layout, so no Python code models a formatter's rules; where it runs and what consumes its output is in the root ARCHITECTURE.md, "API generation".

## Shape

One pass, three stages, no state between runs:

```
definition ──load──▶ Api (frozen dataclasses) ──each selected emitter's validate──▶ selected emitters ──▶ files
```

- `model.py`: `load()` reads the TOML and `from_dict()` turns it into an `Api`. Every language-independent rule in SPEC.md "The definition" is enforced here: identifier syntax, no leading `_` on a name, uniqueness, ranges (every untyped constant, its literal terms and its sum fit its group's `_base_type`, every enum entry its enum's), distinct values within an enum, references (a sum's terms share its base type), lifecycle shape, `_class` lowercase (a class name collision under a binding's casing is that binding's objection), where `_optional` may appear (only on a parameter with a `_ref`, and on a buffer only with `_ref = "in"`), which buffers it produces (`_check_array()`: an `in` or `out` array of a builtin, boxed scalar or struct, or a function's `in` array of an enum, anything else not implemented, as is a `text` parameter), where `_wrote_needed` may appear (an `out` buffer), what a function's `_stack_mb` may name (`_stack_mb()`: an `untyped_const` entry with a positive value; a callback type's is an unknown key), what a union is (`_union()`, after every struct: each member on its own by `_union_member()`, then their shared shape, the prefix by `_prefix()` and each member over it by `_check_member()`, the prefix and each member ending at a whole multiple of the list's alignment by `_check_whole()`, laid out by `_layout()`, the one layout model, which `Api.layout()` also reads, over `_layout_types()`, with `_unlaid()` finding an opaque ref's pointer and `_padding()` a gap, a struct's own or one it holds) and where one may appear (`_check_sequence()`: a parameter with `_ref = "in"` and `_count` of a union with `_mixed_type_list`, a field or by value not implemented), and by what one count type (`_counted_unions()`, after every callback type and function: the first counted parameter's in document order, any other refused), that no derived parameter (`Param.derived_names()`, a buffer's or a callback's) is another parameter's name (`_check_derived()`), what a callback type may say (`_callback()` and `_callback_param()`: a `_return` that can stop, by-value builtins and enums, `in` views, `user_data` reserved) and where a callback type may appear (a function's by-value parameter, never a ctor's: `_param()`, `_field()`, `_check_array()`, `_check_lifecycle()`), a function and a callback type parsed alike by `_signature()`, what a literal sum term may be (parsed once, by `_term()`), which strings may be emitted inside a string literal (`check_literal_text()`, also applied to `--project`), and what a library's name may be (`check_library_name()`, a name beginning with `lib` among the refusals, also applied to `--library`, which reads `naming.library_file_stem()` to name the name a file name holds), each of `_wrapped_api._headers` being relative (neither absolute nor beginning with `../`; stored as written, in list order, none twice), a docstring's lack of a line break, and a plain group's sum's running total term by term (`_check_running_sum()`; a bit group's terms are disjoint, so each of its running totals fits as its terms do). `Api.listed_unions()`, the unions declaring `_mixed_type_list`, the only ones an output renders more than the structs of, and `Api.union()`, a union by name, are what every emitter reads of a union; `Api.c_identifiers()`, every C identifier the header names from the definition, is the one list the loader's `_identifier_clashes()` and the header's union check both read. Every kind is an array of groups, and `_groups()` is the one walk of one, `[[kind]]`, yielding each group as `kind[i]`: `_constant_groups()` parses a constant group whole, as one item; `_named_groups()` splits a named kind's group into its `_docstring` and its items, refusing an item name an earlier group of the kind holds and dropping it, `_parse_items()` parses each item as one item, and `_grouped()` puts the items that parsed back into their groups once every check has run, so the checks across items see flat lists. Failures raise `DefinitionError` with a message that names the table and key, and only the loops catch: each item, a named kind's group's own properties, each struct field and each function parameter is parsed inside an `_Objections` collector, which orders what it records by the item's table, group and place in its group, the cross-item checks run over what parsed, a type whose name another type or a builtin already holds is dropped as a struct that failed is, so the clash reports once, and one `DefinitionErrors` carries every objection in the items' document order (a lone one is raised as itself), except that an unknown top-level table, a missing or malformed `[_general]` or a file that is not TOML stops alone before collection starts. The granularity is uneven by design: a constant group or an enum stops at its first bad entry, while a struct's fields and a function's parameters each report every objection. A reference to an item that failed reports an unknown name, so a failed item's objection is followed by one per reference to it.
- `naming.py`: every SPEC.md "Naming" rule as a pure function of namespace and name, among them `flat_to_string()`, a conversion's name in the Lua and Python modules, the Go binding's spellings (`go_exported()`, `go_enum_entry()`, `go_constructor()` and `go_export_symbol()`, the C symbol of a callback type's exported function, `ns__c`, which no definition's C name can be), the wasm shim's names in the same `ns__` space (`wasm_alloc()`, `wasm_free()`, `wasm_callback_address()`, `wasm_callback_import()` and `wasm_import_module()`), the Node binding's own names (`NODE_NAMES`, `NODE_LOAD`, `NODE_LIBRARY`, `NODE_WASI`, `NODE_VIEW`, `NODE_BYTE_VIEW`, `NODE_ERROR`, and `node_constructor_type()`), `handle_type()`, the Go binding's type and the Python module's class of an opaque ref's raw handle, `library_variable()`, the environment variable naming the Python module's library path, `ERROR`, the Python module's exception class, and `unknown_value_name()` and `NO_FLAGS`, the texts a conversion returns for a value with no entry and for a zero bit value; and `BASE_C_TYPES`, the one map from a `_base_type` to its C type, `<stdint.h>` constant macro and value range, so a new base type is one row; the loader's range checks and the Lua emitter's signed-flag check read the range from it. `integer_range()` is the one statement of an integer type's range, `i8` through `u64`, which `BASE_C_TYPES` is built from and the Python module's argument and answer checks read. `LINK_MODES` (`SHARED` and `STATIC`) and `DEFAULT_LINK` (`SHARED`), and `_LIBRARY_FILES`, the one table of a library file's prefix and suffix by platform and link mode, its `wasi` row the module file the Node binding loads, read through `library_file_name()` and `library_file_stem()`, which strips a table suffix and then the table's prefix: no other module spells a library file's prefix or suffix, and no emitter reads it, since every output renders the library's name. Beside it, `HOST_PLATFORMS`, from the value Python's `sys` module reports to the table's platform, which the Python module's emitter writes into its output as the table of the file to load, `LOADER_PATH_VARIABLES`, each platform's loader search variable, which the compiled tests read, and `GO_OS`, each platform's GOOS, which the Go binding's static link lines name; no module outside `tests/` reads the host's platform, so the generated text is the same on every host (`tests/test_cli_emitters.py` scans code tokens for a read, so the Python module's emitted `_sys.platform` is text, not a read, and the text of every f-string, whose replacement fields Python 3.11 tokenizes as text). Emitters never build a generated name by string concatenation of their own.

An `emit` assumes its `validate` returned nothing and does not check again. An emitter is the protocol's five names and nothing else public: what emitters share is a language fact, in that language's module, and what one emitter alone uses, its own keyword table included, is private to it. Emitters share the model, `naming` and the language modules, and never import one another.
- `__main__.py`: the command line, emitter-blind: it imports no emitter, only `EMITTERS`. Parses arguments, loads, runs each selected emitter's `validate` and reports every objection at once, one line each; a message several emitters raise identically prints once, its line naming every one of them, comma-joined in `EMITTERS` order (`header, wrapper, stub: ...`). It then runs the selected emitters in memory and writes, so a failing definition leaves no partial output; a `ToolError` from an `emit` is reported as `langxyne: <message>`, exit 2, before anything is written. With `--check` it writes nothing: `_check()` compares those in-memory texts, formatters already run, with the files under `--generated`, read back as text with universal newlines, so line endings are aside, and opens no file for writing. The registry's keys are the vocabulary `--outputs` accepts (`TOKENS`); generation calls each selected module's `LABEL`, `validate`, `output_path` and `emit` and nothing else, and `gendeps` calls `output_path` too, so each output's path is stated once, by its emitter. `--project`, `--library` and the definition's file name, which every banner carries, are checked in one place, `_flag_objections()` (not empty, and the rule of what each names, `model.check_literal_text()` and `model.check_library_name()`), their objections printed after the definition's in the same run. `--library`, else `_general._bound_library`, and `--link` (`naming.LINK_MODES`, its values argparse's choices) are resolved once, onto `api.library` as a `model.Library` by `dataclasses.replace`, before any emitter's `validate` runs, so the missing library and an unacceptable link mode are objections each output that loads or links raises from `validate(api)` (`lua`, `rs`, `go` and `py`) and the generator names no output for them; a refused `--library` still stands in for the definition's, so it draws its own objection and not the missing library's. Every objection, the loader's, the emitters' and the flag's, prints through one helper, `_report()`, which `gendeps` shares. It always writes what is selected; whether it runs at all is make's decision, from the definition's mtime. Its `gendeps` mode loads the definition for its `_general._name` and prints a make fragment from the same `output_path` and `companions` calls, so the naming rule has a single home and a consuming build file carries none of it: `GENERATED :=` lists each selected output followed by its companions, and one grouped-target rule runs the generation mode over the definition with the same `--outputs` and, where it is not the default, `--link`. A consuming makefile includes the fragment and defines `GEN`, `BASE` and `LANGXYNE`, and chooses the selection it passes to `gendeps` as `--outputs`. A dropped output's file stays under the generated directory, so a build that narrows the selection cleans that directory.
- `api_def.schema.json`: a hand-maintained JSON Schema (draft 2020-12) of the definition's shape, its keys and value types, for editors (Taplo) to complete, describe and flag keys before generation. `load()` reads it when the `jsonschema` package imports and `--no-schema` is absent, and runs it over the parsed TOML before `from_dict()`; a definition it refuses draws its objections in place of the loader's. `model.py` stays the authority on every rule, and nothing checks the schema against the loader, so a change to the loader's keys is mirrored here by hand.

## The model

`Api` is a frozen dataclass tree whose every item is a `Node`, a keyword-only base carrying `name` and `docstring`: `Group` of `BitConst`, of plain constants as `EnumEntry`, of `StringConst`, or of a named kind's items; `TypedConst` of `EnumEntry`; `OpaqueRef`; `BoxedScalar`, carrying its `base_type`, one of `INTEGER_TYPES`; `Struct` of `Field`; `Union` of `UnionMember`, each its tag constant's and its struct's names, the union carrying its inferred `prefix`, the struct every member's begins with, `tag_field` and `length_field`, the names of the prefix's fields holding the tag and the record's byte length, which `Api.prefix_fields()` gives as the fields themselves, so no emitter finds either by its position in the prefix, `mixed_type_list`, and `count_type`, the one `_count` of its counted parameters, `u32` where none counts it, which the header's helpers take for counts and extents; `Function` of `Param`, a function's or a callback type's signature alike, a function's `stack_mb` the `untyped_const` entry its `_stack_mb` names, read by the Node binding alone. `Api` itself and its optional `WrappedApi` are not nodes. Tuples throughout, in document order. Every kind is a tuple of `Group`s on `Api`, each carrying a docstring and a base type (`None` for a string group and for a named kind's), for the emitters that render one block per group; a group has no name in the definition, so its `name` is where it is, `untyped_const[0]`; `Api.bit_consts`, `Api.consts` and `Api.string_consts` are every entry across a kind's groups in order, for everything that treats constants one by one: literal values, composition, uniqueness, pins; and `Api.typed_consts`, `opaque_refs`, `boxed_scalars`, `structs`, `unions`, `callbacks` and `functions` are properties flattening `typed_const_groups`, `opaque_ref_groups`, `boxed_scalar_groups`, `struct_groups`, `union_groups`, `callback_groups` and `function_groups` the same way, so everything that treats a named kind's items one by one reads no group. `headed()` pairs each item an output renders together with its group's docstring where it is the first of that group's items in the run, else `None`, every item of the groups in document order by default or a run an emitter names, as a class's `ClassShape.functions()` (ctor, methods, dtor): the one statement of where a named kind's group docstring renders, which every emitter reads. A composed entry (a list of terms, each an earlier same-table entry or a literal integer) carries both its resolved `value` and its `parts` in the order written, each the entry's name or a `LiteralTerm` holding the literal's value and the base it was written in, since the header renders a sum symbolically from `parts` while every other emitter uses `value` directly; no emitter parses a term again; the loader refuses a bit-group sum whose terms share a bit, and any sum with a term of another base type. `Api.constant_names()` lists every constant with where it is written, enum entries included unless asked not to and the version constant where asked: the one walk of the constants, read by `names()`, the loader's uniqueness check, the header's macro check and the bindings' namespace and module checks. `Api.classes()` is the class shape every binding builds, one `ClassShape` per opaque ref with a `_ctor`: the ctor, its handle parameter, the other `out`s it caches, the methods and the dtor. A method is any other function whose first parameter is the opaque by value, the one membership decided by a parameter's shape, since SPEC.md states it that way; `Api.free_functions()` is every function no class renders as its ctor, a method or its dtor, in document order, which the Go and Python bindings render at module scope. `ClassShape.drives()` says whether a method of the class takes a callback, the one condition under which every binding refuses the class's object, as receiver or argument, while a call of it is in progress. `ClassShape.class_params()` is the parameters a class renders, each of the ctor's and each method's but its first, the one scope of every binding's refusal of a parameter named like a name its class code uses, since a parameter no class renders reaches a binding only through its raw declaration; `ClassShape.members()` is the class's member list, the binding's own fixed members, then the methods and the cached `out`s, for each binding's class duplicate check. `Api.success_entry()` is a function's zero-valued result entry, a callback's continue, and `Api.stop_entry()` a callback's first non-zero one, what a binding answers where the consumer's code failed, which `Api.first_nonzero_entry()` gives, `None` where an enum has none, for any function: a binding answers it too for a method refused while a call of its object drives a callback; `Api.callback()` is the callback type a parameter names. `duplicates()` is the one duplicate-name finder over `(where, name)` pairs: the loader's C-identifier uniqueness check and each binding's namespace, enum-class, module-field and class-member checks build their objections from it, every binding through `duplicate_objections()`, the one wording of a name defined twice; `generated_name_objections()` is the one wording of a definition name the generated code itself uses where it would be in scope. A bit or plain `Group` and a `TypedConst` carry `to_string`, the `_to_string` name or `None`; a string group's is always `None`, since the loader refuses the property there as an unknown key. `single_bit_entries()` is the one statement of which bit entries a conversion decomposes a value into, read by every emitter that renders one, and `named_values()` its counterpart for a plain group, one entry per value, the later where two share one, read by the C++, Lua and Rust conversions. `Api.kind()` answers the one question every emitter asks, which category a type name belongs to (`builtin`, `text`, `enum`, `opaque`, `boxed`, `struct`, `union` or `callback`), from the validated tree rather than by re-checking, `text` being a builtin every output renders as a struct; a boxed scalar needs no rule of its own in the loader beyond its table, since `_return` already admits only a `typed_const`. `Api.layout()` is a type's C size and alignment, the same on every target, from the loader's one layout model, which the union's checks read, and `Api.field_offsets()` each field's offset in a struct or the text type, which `_fields_layout()` computes in the same walk, read by the relay's `_scalars()` and the Node binding's readers and writers; `Api.list_alignment()` is a union's list's, the prefix's, which the loader holds every member to: the unit of every binding's `at` and the word of the relay's buffer. `Api.uses_text()` says whether some struct field is `text`, the one condition under which every output renders the text type, its resolver and their names, and each output's duplicate check counts them. `Api.uses_64_bit()` says whether some value position holds `i64` or `u64` — a struct field, a function's or callback type's parameter (a typed array's element included) or return, or a boxed scalar's `_base_type`; a buffer's `_count` is a count width, not a value — the one condition under which the Lua emitter writes the support module beside its binding. `Api.names()` lists every name the definition gives with where it is written, `_to_string` names included (`typed_const.result._to_string`, `untyped_bit_const[0]._to_string`), so each emitter's `validate` checks its own keywords over one walk of the tree.

Normalisation happens on the way in. A described item's `_` properties are split from its members first, so no member check ever sees a property. `_attributes()` turns a naked value into the table it is sugar for, so a bare type string and a `{ _type, ... }` table become the same `Param` or `Field`, and a bare integer and a `{ _value, _format, _docstring }` table the same `EnumEntry`; `tomllib` already makes a nested `[a.b.c]` table and an inline one the same dict. `Param.ref` is `None` or one of `in`, `out`, `inout`; `Param.count_type` is set for every buffer, `memory`, a typed array, whose `type` is its element, or a sequence, whose `type` is its union and which `Param.is_union` marks, `Param.wrote_needed` only on an `out` buffer, and `Param.callback` on a function's parameter of a callback type. One buffer concept: `Param.is_buffer` is the one test of a buffer, every buffer rule (the count, `_optional`, the ctor refusal, `_wrote_needed`) lives in the loader once, and `Param.derived_names()` is the one expansion of what a parameter brings after itself in C order, a buffer's count and reports, a sequence's count and byte extent, or a callback's `p_user_data`, which the name checks read whole; a reader of one of them goes through its named accessor, `count_name()`, `report_names()`, `bytes_name()` or `user_data_name()`, as `c.c_params()`, `rust.ffi_params()`, `rust.implementation_params()`, the relay's locals and every binding's marshalling do, so no emitter spells a suffix or slices the expansion by position. An emitter tests `type == "memory"` only where bytes and records render differently. Emitters see one shape.

Order is document order because `tomllib` builds insertion-ordered dicts, a guarantee Python makes since 3.7 that the TOML specification does not. The loader's docstring states the reliance; it is the one place the project depends on it.

## What the emitters cannot express

- `_optional` is documentation only in the C header, which has no expression for it, and in the Rust relay, which hands every pointer over as an `Option` whether or not it is `_optional`; the C++ wrapper, the Lua module, the Rust binding, the Go binding and the Python module render it, as an optional pointer parameter, a nil-admitting argument, an `Option`, a nil-admitting pointer or slice and a `None`-admitting argument respectively, the Lua and Python modules returning an `_optional` `out` rather than taking it.
- The spelling of numbers as written. `tomllib` yields integers, so the definition says `_format = "hex"` where it wants hex; without it a value is decimal whatever the file said.

## Extension points

- A new output: copy `Emitter`'s five signatures into a new `emitters/emit_<what>_<flavor>.py`, its `output_path` naming a path under the output directory that mirrors where it will be staged, or, for a file nothing stages, under the subtree of its kind (`stub/`, `rust/`), and add one line to `EMITTERS`, its token to the module. `emit_stub_cpp.py`, `emit_abi_rs.py` and `emit_binding_cpp.py` are the worked examples.
- A per-API hooks module beside the definition is reserved for peculiarities. Its interface is deliberately undefined until the first real case shows what it needs; the model is plain data so a hook can adjust it without the generator knowing why.
